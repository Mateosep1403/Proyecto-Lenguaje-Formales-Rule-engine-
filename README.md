# Project Description

This project implements a rule-based language interpreter developed for the Formal Languages course.

The system supports:

- Lexical analysis
- Syntactic analysis using a hand-written LL(1) parser
- Abstract Syntax Tree (AST) construction
- Rule execution using fixed-point evaluation
- Static analysis of rules

The language allows defining rules of the form:

```txt
rule r1:
if temp > 30 then alert
```

# Supported Language Features

## Conditions

- Comparisons:
  - `>`
  - `<`
  - `=`

Example:

```txt
temp > 30
humidity < 50
```

## Facts

Facts are identifiers that become active during execution.

Example:

```txt
alert
fan_on
```

## Logical AND

Example:

```txt
temp > 30 AND humidity < 50
```

---

# Execution Model

The interpreter evaluates rules iteratively using fixed-point semantics:

1. Initial facts are loaded
2. Rules are evaluated
3. New facts are activated
4. The process repeats until no new facts are generated

---

# Input Format

The input file contains:

1. Rules
2. Initial state separated by `---`

Example:

```txt
rule r1:
if temp > 30 then alert

rule r2:
if alert then fan_on

---
temp = 35
humidity = 40
```

# Static Analysis

The system detects:

## Conflicts

When multiple rules generate the same action.

Example:

```txt
Action fan_on generated by r1, r2
```

## Redundant Rules

When two or more rules have the same condition and action.

Example:

```txt
Redundant rules: r1, r2
```

## Potentially Inactive Rules

Rules that may never be activated.

Example:

```txt
Potentially inactive rule: r3
```

# Implemented Components

## Lexer

Transforms the input text into tokens.

## Parser

Implements an LL(1) recursive descent parser.

## AST

Represents the structure of the program using Python classes.

## Interpreter

Executes rules using fixed-point evaluation.

## Static Analysis

Detects conflicts, redundancies, and inactive rules.
